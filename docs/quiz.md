# Module quizzes

Every module can have a quiz. **A module is completed only by passing its quiz with 90% or more.**
Modules with no active questions still use the plain "Mark as complete" button.

## Question types

| Type | Learner does | Stored `content` | Answer sent by the phone |
|---|---|---|---|
| MULTIPLE_CHOICE | picks one option | `options[]`, `correct` (index) | int |
| TRUE_FALSE | True / False | `correct` (bool) | bool |
| MULTIPLE_SELECT | ticks all that apply | `options[]`, `correct[]` (indexes) | list of ints (any order) |
| MATCHING | matches each left item to a right item | `pairs[{left,right}]` | `answer[i]` = pair index matched to left i |
| ORDERING | drags items into sequence | `items[]` stored in the correct order | list of item indexes |
| IMAGE_CHOICE | looks at a picture, picks one | `media_asset_id`, `options[]`, `correct` | int |
| NUMERIC | types a number | `correct`, `tolerance`, optional `unit` | number |

Options, right-hand sides and ordering items are shuffled on the phone for each attempt; answers are
graded in the original index space. There is no partial credit: a question is right or wrong.
Retries are unlimited; the best attempt is shown.

## The 90% rule

Passed means `correct * 100 >= 90 * total`, using integers (no rounding surprises).
Phone and server share `tests/quiz_vectors.json` (30 answer cases, 12 pass cases), generated by
`scripts/generate_quiz_vectors.py` and replayed by pytest and `flutter test`.

## Flow

1. Admin writes or edits questions: **Content → module → Manage the module quiz** (CONTENT_ADMIN, SUPER_ADMIN).
2. Questions (with answers) are included in the next **published release**. Phones receive them on sync,
   so a new or edited quiz appears only after you publish a release.
3. The phone grades offline and saves the attempt. The "Mark as complete" button is enabled only once the best score is 90% or more.
4. Sync uploads quiz attempts first, then progress.

## Server checks

- `POST /sync/quiz-attempts` is idempotent per `client_id`. The server recomputes `passed` from the
  reported counts and ignores the phone's `passed` flag.
- A module that has active questions cannot be marked completed without a passed attempt;
  the progress item is rejected with `quiz not passed`.
- Grading is done on the phone, so counts are client-reported. This enforces the rule against honest
  clients and accidental bypasses; it is not tamper-proof against a modified app.

## Seeding starter questions

```
cd backend
python -m scripts.seed_quizzes            # adds questions only to modules that have none
python -m scripts.seed_quizzes --replace  # rebuilds them
```

the module text only, with the source quoted in each explanation. **A subject-matter expert must review
them before real rollout.**
